# 活動履歴と業務更新の運用

## 活動をどこへ紐づけるか

案件は「どの商談がどう進んだか」、業務は「そのための具体的な仕事がどう進んだか」を管理します。連絡手段や相手が社外かどうかだけで判定しません。

| 事実 | 主な紐づけ先 |
| --- | --- |
| 顧客へ商品・価格を提案した、顧客から条件の返信が来た | 案件 |
| 顧客が資料やサンプルを希望した | 案件。その対応が必要なら別に具体的な業務を作る |
| 仕入先へ資料を依頼した、資料を受け取り確認した | 資料取得の業務 |
| 荷物を梱包した、発送準備を完了した | 発送業務 |
| 顧客へ資料を提出した、サンプルを発送した | 商談の経緯として案件。該当する業務の完了条件にもなる場合は業務の更新を確認 |
| 対象が分からない | 単独履歴または要修正。推測で相手や仕事へ付けない |

関連案件を持つ業務への活動は、その案件にも紐づく場合があります。同じメール・事実を案件用と業務用の2件に複製しません。送受信の実際の相手と日時を残します。

## 取込カードから業務を更新する

1. 活動候補の本文と根拠を確認する。
2. 「活動履歴の紐づけ先」で「業務：W番号 件名」を選ぶ。
3. 「活動後の業務を更新」の現在状態と次のアクションを確認する。
4. 状態を変更するなら「活動後の状態」を選ぶ。催促などは「変更しない」。
5. 次のアクションも変えるならチェックして入力する。空欄は明示的な解除。
6. AIの提案がある場合は理由を確認し、「提案を入力欄へコピー」してから必要に応じて修正する。表示しただけでは採用されない。
7. 変更内容の確認チェックを入れ、「活動を記録して業務を更新」を押す。
8. 業務カードが選んだ列にあること、次のアクション、活動と変更履歴を確認する。

状態も次のアクションも変更しない場合は「業務へ履歴を反映」です。案件・単独履歴を選ぶと業務更新欄は表示されません。紐づけ先を変えると入力中の業務更新内容はリセットされます。

営業案件のステージは、この操作では変更しません。過去の活動を取り込むときも、現在の業務を過去の状態へ戻す必要があるとは限りません。

## 業務状態の基準

状態の列は一本道の工程ではありません。必要な列へ直接移り、状況次第で戻ることもあります。

| 状態 | 入れる条件 | 次の状態を判断するきっかけ |
| --- | --- | --- |
| 未着手 | 担当と仕事は決まったが、作業に着手していない | 情報の確認や準備を始めたら確認・準備中。実作業を始めたら対応中 |
| 確認・準備中 | 実作業に必要な情報、対象、条件、資料の内容を自分で確認・準備している | 前提が揃い、実作業を始めたら対応中。依頼後は適切な待ち先へ |
| 対応中 | 梱包、書類作成、送付など、成果物や実行に向けた作業をしている | 外部へ依頼して返答が必要なら相手待ち、社内へ依頼して止まるなら社内待ち |
| 相手待ち | 社外へ依頼済みで、返答や提供物がないと次の作業を進められない | 返答が届いたら、内容確認は確認・準備中、すぐ実行できるなら対応中。催促だけでは列を変えない |
| 社内待ち | 社内の承認・判断・他担当の作業を依頼済みで、それを待っている | 回答後は確認・準備中または対応中。明確な判断事項が残るなら要判断 |
| 要判断 | 価格、方針、対応可否などの具体的な判断事項があり、進め方が未決定 | 判断者と論点を次アクションへ書く。決定後は実際に行う作業や待ち先の列へ |
| 保留 | 続けるか再開時期を決めておらず、一時停止すると決めた | 再開条件や確認日を記録。再開したらその時点の作業・待ち先へ |
| 完了 | 業務カードに書いた完了条件を満たし、この仕事として残作業がない | 新たな別の仕事は新規業務。誤完了なら理由を残して該当状態へ戻す |

依頼送信と成果物受領は別です。「資料を顧客へ提出する」業務は、仕入先から受け取っただけでは完了しません。「仕入先から資料を取得する」業務なら、対象と内容の確認までを完了条件にするなど、カードのメモへ明記します。

## 例：農薬資料を顧客へ提出する業務

- 仕入先へ依頼した：相手待ち。次アクション「返答予定日に取得状況を確認」。
- 資料が届いた：確認・準備中。次アクション「対象商品・発行日・対象国を確認」。
- 対象が違っていた：相手待ち。次アクション「正しい商品の資料を再依頼」。
- 資料が使えると確認できた：対応中。次アクション「顧客へ資料を送付」。
- 顧客へ送付した：送付が完了条件なら完了。顧客の受領確認までが条件なら相手待ち。

## 保存が途中で失敗した場合

活動、業務更新、業務の変更履歴は別の保存です。一括のトランザクションではありません。

- 業務が確認時点から変わっていたら、活動と更新の保存前に止めます。再読み込みして確認します。
- 活動保存に失敗したら業務更新は実行しません。処理中・結果不明の候補は重ねて反映できません。
- 活動だけ保存され、業務更新で失敗・競合した場合は警告が出ます。活動を再登録せず、業務の現在値を確認して必要な修正を業務画面で行います。
- 活動と業務が保存され、変更履歴だけ失敗した場合も警告が出ます。候補の詳細に保存した変更内容を確認します。
- 保存済み候補の再反映では、業務をもう一度更新しません。
